Epic 5 — Behavioral Data Infrastructure Wireframes

The compounding-moat layer for the commercetools Next-Gen Frontend. Behavioral collection silently activates when a CT project is connected (Epic 1) and accumulates before any analytics UI is built. Core product decision: there is no separate ACI analytics dashboard — behavioral data is dissolved into the canvas surface (heatmap overlay, engagement badges, drop-off annotations). IT Admin surfaces handle dual-consent configuration and pipeline health.

1 — Canvas with Behavioral Overlay

Behavioral insights dissolve into the canvas surface Business Operators already use every day. There is no separate ACI analytics dashboard. Operators toggle a heatmap overlay on top of live components, read engagement score badges per section, and hover to see drop-off rates with suggested fixes. This is how FR21–FR26 surface: contextually, inside the work.

Design Notes

  • Dissolved into the canvas — heatmap is an overlay on the live editor, not a separate dashboard. Operators already scan the canvas; behavioral layer reuses that gaze. (FR21)
  • Heatmap toggle in the context bar — one click turns the overlay on/off. Heat intensity follows a cool-to-hot gradient (blue → yellow → orange → red). (FR21)
  • Engagement badges per section — green ≥80, amber 50–79, muted <50. A glance reveals which sections earn their canvas real estate. (FR22)
  • Drop-off annotations — each section carries its rolling 7-day drop-off rate on the top-left corner. Warn threshold 25%, critical 50%. (FR21)
  • Hover cards — dwell on any section to see raw session counts, CLV-tier breakdown, and the ACI flag reasoning. No context switch required. (FR23)
  • Behavioral panel replaces Properties contextually — right sidebar switches to the Behavioral tab when the operator selects a section with flagged insights. Click "Apply in editor" jumps back to Properties. (FR24)
  • Red Zone remains Red — CheckoutCTA shows explicitly that behavioral collection is disabled to satisfy the PCI boundary (FR49). The absence of a heat zone is itself the design affordance.
  • No dashboard to navigate to — operator never leaves the canvas to "check analytics." The moat layer is where work already happens. (FR21, FR27)

Design Notes

  • Badges-only mode — operators editing content don't always want a heatmap. Badges stay on by default because they're compact; heatmap is opt-in. (FR22)
  • Properties tab remains primary — when the operator is actively editing, the sidebar stays in Properties mode with an at-a-glance page-level insights card at the top.

Design Notes

  • ACI Analyst is a notification surface, not a dashboard — it is a focused inbox reached from the nav rail. Every row is actionable; every action deep-links back into the canvas. (FR23, FR24)
  • Severity pills match heatmap semantics — critical = red (matches hot zones), warning = amber, info = blue. Consistent across the whole product. (FR23)

2 — Dual-Consent Management (IT Admin)

Two legally distinct consent layers, configured independently per tenant. Aggregate behavioral consent governs ACI collection (anonymized sessions, heatmap data, drop-off events). Identity-linked personalization consent governs CLV-enhanced rendering tied to a known consumer profile. The two are separate legal bases under GDPR Art. 6 and must never collapse into a single toggle. IT Admin also manages the right-to-erasure queue and data retention windows from this surface.

FR26 FR28 FR47 FR48 FR49

2A — Dual-consent layers: separate toggles, scopes, and audit

ConsentManager · two independent legal tracks
Critical design principle: these two consent layers are visually adjacent so operators see the distinction, but configured independently. A consumer can consent to aggregate behavioral collection without consenting to identity-linked personalization, and vice versa. The tenant-admin configures the defaults and the scope; the runtime consent banner (shown to end-consumers) respects both.

Design Notes

  • Two layers, never one — the visual separation is non-negotiable. Collapsing them into a single toggle would be legally ambiguous and reduce the moat (operators would default both ON or both OFF).
  • Distinct accent colors — aggregate = sky blue, identity = fuchsia. The color carries the legal basis across every reference in the product (audit log, erasure queue, pipeline diagram). (FR26)
  • Legal-basis chip under each header — Art. 6(1)(f) legitimate interest vs Art. 6(1)(a) explicit consent. This is the only place in the product where we surface statute references; it's what IT Admins and their DPO need to sign off. (FR47)
  • Scope lists are read as a policy document — green checks for what's in scope, red crosses for what's explicitly excluded. Never a vague "other". (FR49 PCI exclusions, FR26)
  • Stop-on-withdrawal is defaulted ON and disabled to OFF — FR47 is a hard requirement. The toggle is shown for transparency; some regions forbid turning it off.
  • Regional overrides shown at the bottom — the system computes the stricter of (tenant setting, regional minimum). Operators can't accidentally loosen below GDPR/CPRA floors.
  • Consent rate metrics use the layer's accent color — reinforces which layer each number refers to.

Design Notes

  • Scope column shows which layer is being erased — most requests hit both; some only identity (consumer is keeping anonymous session tracking but ending personalization). The two accent colors make this scannable. (FR48, FR26)
  • Days-left countdown is color-coded — green >10d, amber 4–10d, red <4d. Overdue rows surface a "Fast-track" primary button to collapse the fulfillment path. (FR48)

Design Notes

  • Retention configured per layer, independently — aggregate gets a longer default (730d) because the legal basis (legitimate interest) supports a longer cohort window; identity gets 365d because explicit consent carries a higher proportionality bar. (FR28)
  • Slider with color-coded risk gradient — green → amber → red from short to long. The visual cue reminds admins that longer retention = higher compliance exposure.
  • Regional ceilings displayed inline — EU tenants hit a hard ceiling on identity retention at 365d under the current DPA template. The marker is draggable only within the region-allowed band.
  • Audit log is immutable, append-only — every config save, every erasure, every consent withdrawal, every regional override is logged with actor, timestamp, and layer. No delete. No edit.
  • System actors distinguished by badge color — green avatar = automated system action; blue = IT admin; amber = policy engine. The DPO is color-independent because they wear multiple hats.
  • Consent withdrawal latency logged — row 4 shows "halted <50ms" as proof of FR47 compliance. This latency is also tracked on the Pipeline Health tab.
  • Export-to-CSV available at the top right (implicit) — DPO workflows frequently need audit exports for regulator inquiries.

Design Notes

  • Dense metric grid is the whole point — this surface communicates "the system is working, nothing for you to touch" at a glance. It is diagnostic, not analytical. (FR25, FR28)
  • Status indicator dots per card — green = within SLO, amber = degraded, red = alert. One visual rule governs the whole screen.
  • Left-to-right pipeline diagram — storefront beacon → edge validator → Kafka → ClickHouse. Mirrors the architecture in tech-spec-mvp.md. The expected filter ratio is called out explicitly so on-call engineers don't treat it as data loss.
  • Withdrawal latency is first-class metric — FR47 requires immediate halt; we surface the p95 measurement as proof. 34ms is dramatically inside the "immediate" threshold.
  • Event-type breakdown uses mini horizontal bars — share-of-volume is glanceable; anomalies (rage_click +14%) are color-flagged. (FR22 foundation, FR27)
  • No "last updated" timestamp on the whole page — everything is live. A timestamp would invite operators to refresh; the data already is real-time.

Design Notes

  • PCI boundary grid dominates the screen — six green-left-bordered cards lined up shouts "compliant." Any single card flipping to red (via the .fail modifier) becomes the page's strongest visual focus immediately. (FR49)
  • Synthetic probes referenced explicitly — checkout exclusion verified every 5 minutes, cross-tenant isolation verified 24 times daily. Proofs, not claims.
  • Alerts use the same severity pill system as the consent audit and ACI inbox. Consistent severity language across the product.
  • Rage-click auto-escalation — an info-severity pipeline alert that auto-hands off to ACI Analyst. This is the pipeline-to-insight bridge in action. (FR23)
  • Retention sweep shown as a routine alert — 84.2M rows tombstoned at 2am sweep. Normalizing the compliance work as "just how the system runs."
  • Residency lock is a one-way door — once tenant is provisioned to EU, no admin action can move data to US. This is a hard constraint surfaced visibly. (Epic 6 FR43)
  • Quarterly re-attestation date visible — the QSA letter expiration is surfaced so admins see it before it lapses.
Wireframes are intentionally low-fidelity — dashed borders and placeholder content indicate where customer-brand content will render.
