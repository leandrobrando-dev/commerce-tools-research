Epic 1 — Platform Foundation & Operator Workspace Wireframes

Foundation surfaces for the commercetools Next-Gen Frontend: project activation (Storefront Developer), the Operator Workspace home (Business Operator), and the Pages Manager. Direction follows the chosen UX: Merchant Center Native shell + expandable Split Studio AI panel. Epic 1 also activates behavioral collection (Epic 5) and ships the Epic 6 skeleton (SSO + data residency at procurement).

1 — Tenant Activation & Project Connection

First run. A Storefront Developer (with IT Admin sitting alongside) connects an existing commercetools project to the Next-Gen Frontend. This single flow is the procurement gate — SSO selection, data residency choice, and the behavioral-collection consent decision all happen here, because all three are legal/contractual decisions that cannot be retrofitted later. Once activation completes, the behavioral events pipeline is silently armed and the Operator Workspace is provisioned.

Design Notes

  • Wizard lives inside MC shell — same topbar, breadcrumb pattern, user avatar. Developers never leave Merchant Center. (FR34)
  • Four steps visible upfront — the sidebar makes the entire procurement gate transparent. No surprise "one more thing" later.
  • Project region auto-detected, not selected — pulled from CT metadata. Prevents a mismatch between CT project region and storefront residency. Storefront residency is a separate step 2 decision.

  • Density matches Merchant Center developer surfaces — monospace font on IDs, concrete scope names, latency numbers. Operators never see this screen.

Design Notes

  • Three legal decisions collapsed into one page — residency, SSO, behavioral consent are all contractual at activation time. Splitting them across screens makes it too easy to defer or misalign. (FR40, FR44, FR26)
  • Residency warning is prominent, not buried — amber bar explicitly names the consequence: "behavioral history does not transfer." The moat narrative is honest.
  • SSO selection ships a real skeleton — SAML + OIDC are selectable; MC session auth stays available. Epic 6 full SCIM/governance comes later but the procurement gate works today. (FR40)
  • Behavioral consent is violet-tinted, not alarming — it's an AI-era decision framed as "arm the moat" rather than a legal warning. The fine print clarifies the PCI/consent boundaries explicitly.
  • DPO cue in context bar — "Legal & contractual decisions — review with your DPO" warns IT Admins this isn't a developer-only click-through.
  • Activate button copy is deliberate — "Activate tenant →" not "Finish." The moment of commitment is named.

Developer handoff — bootstrap your component library

The Operator Workspace is ready, but there are no pages or components yet. Install the CLI, scaffold a library from your existing Frontastic/Next.js codebase (or start fresh), and publish via the Developer Console (Epic 2).

# 1. Install the CLI
$ npm i -g @commercetools/ngf-cli
# 2. Login with your SSO
$ ngf auth login --tenant tutorial
# 3. Scaffold the library from an existing codebase
$ ngf scaffold --from ./frontastic-src --out ./ngf-library
# 4. Open the Developer Console → Component Library
$ ngf console open

Design Notes

  • The moat starts before the UI — the receipt explicitly calls out "Behavioral events started flowing at 14:22:06 UTC." This is Epic 5 infrastructure activating inside Epic 1. (FR25)
  • Metric cards summarize the entire procurement gate — region, SSO, behavioral, next milestone. Legal/IT can screenshot this for their records.
  • Activation ID shown monospace — support reference, audit trail. Enterprise trust signal.
  • CLI block is the real handoff — developers need to scaffold the component library (Epic 2) before operators can do anything. The wizard doesn't pretend this step is optional.
  • "What's next" roadmap — shows the epic sequence without BMad jargon. Step 4 (Epic 6 full) is muted so IT Admins see where to return later without feeling behind.
  • Go to Operator Workspace button in context bar — the CTA for the Business Operator is always one click away even while the developer is absorbing the receipt.

2 — Operator Workspace (Home)

Where the Business Operator lands after logging into the Next-Gen Frontend. Warm, approachable, skimmable. Surfaces draft work that needs attention, publish status, AI suggestions from the governed library, behavioral signals that arrived overnight, and the onboarding checklist while the tenant is still young. This is the day-to-day home — more dashboard than editor, but with every card a deep link into Epic 3/4/8 surfaces.

Design Notes

  • Greeting is human — "Good morning, Sasha" + "your storefront is 3 days old — the moat is just starting to form" localizes the moat language to something an operator can feel proud of without jargon.
  • Four top metrics frame the day — Pages / Draft changes / Published last 7d / Tenant intelligence. Every card deep-links. (FR22, FR61)
  • Drafts card pulls attention where it's needed — stale staged content (2 days, no feedback) gets a warm amber bar, not a red alarm.
  • Recent activity includes the AI agent — "collected 218 behavioral sessions overnight" reminds operators the moat is working silently. Matches Epic 3 audit log pattern.
  • AI suggestions card is honest about calibration — first tile is actionable (a library completion), second is a muted "Optimize unlocks in 1,790 sessions." Never promises what the engine can't yet deliver. (FR56)
  • Onboarding checklist progresses visually — violet bar matches the AI accent; 4 of 7 complete. Never forces dismissal; users close when ready.
  • Team card surfaces invite status — "2 invites pending" is a gentle nag to the IT Admin without being a red alert. (FR42)

Design Notes

  • Same shell, different density — onboarding checklist gone, intelligence score takes its place in the right rail. Progressive disclosure from young → mature tenant. (FR61)
  • Top AI recommendation is the hero card — replaces "draft changes" as the priority surface once the engine is producing real recommendations. (FR56)
  • "Your data shows" language, not "AI thinks" — recommendation copy attributes the insight to the operator's own session data. Confidence card principle from Epic 8.
  • Expected lift is specific with a confidence interval — "+4.2% add-to-cart (95% CI: +2.8% to +5.6%)" builds trust. Never just "we recommend this."

  • Greeting personalized but less onboarding-centric — "Thursday, 7 May" + "43k sessions last 7 days" treats the operator as a veteran.

3 — Pages Manager

The list/grid surface operators land on when they click into "Pages" from the nav rail. Every storefront page — live, draft, or staged — with its status, last-edited metadata, engagement signal, and B2X context scope. Filtering is built around the B2X × locale × customer-group axes operators already navigate in the editor context bar. Includes a grid view, a table view, and the "New page" flow. Governance is visible throughout (which pages reference Red Zone components, who last touched them).

Design Notes

  • Grid cards are at-a-glance scannable — thumbnail preview, title, URL, context chip, status chip, last-edited avatar, Red Zone count. One line per concern.
  • Status is encoded both by border and chip — amber border for draft, violet border for staged, neutral for live. Redundant encoding for accessibility.
  • Engagement badge lives on the preview — score 54 (needs attention) shown warm-amber, 92 (high) shown green. Same language as Epic 3 canvas. (FR22)
  • B2X context avatars on non-B2C cards — B2B (violet) and Dealer (red) mini-avatars sit in the preview top-left so operators never mistake which context a card represents. (FR5)
  • Red Zone count is surfaced per page — "🔒 3" tells operators which pages depend on platform-managed components before they start editing. (FR15)
  • Filter sidebar mirrors the editor context bar — same B2X × locale × status axes. Zero conceptual translation between surfaces.
  • "Create new page" tile is the empty final cell — inline CTA instead of a modal. Hints at template + AI paths (Epic 4).

Design Notes

  • Table view is the power operator surface — keyboard-navigable, sortable, bulk-selectable. For operators managing 50+ pages across brands.
  • Bulk actions bar appears contextually — amber strip with "3 pages selected" + Stage / Archive / Duplicate / Bulk publish. Mirrors MC patterns.
  • Checkout row is explicitly PCI-boundary marked — "Platform" author + 🔒 All + not-allowed cursor. Operator understands this page isn't theirs to edit. (FR15, FR49)
  • Dynamic template rows named clearly — "/p/:sku · dynamic template" tells operators they're editing one template that renders for many SKUs.
  • B2X context shown as inline colored label — blue B2C / violet B2B / red Dealer — same color identity as Epic 3's context switcher.
  • Engagement column uses color thresholds — green ≥70, amber 50–69, red <50. Staged rows show "—" (no data yet).
  • Last-edited shows avatar + relative time — Platform-authored pages (checkout) explicit, not mysterious.

Design Notes

  • Three starting paths, honestly labeled — blank / template / AI-scaffold. AI path is marked "Epic 4" so operators see what's available now vs. later, without hiding it.
  • B2X context is a first-class choice, not an afterthought — operators commit to scope before they start drafting. Prevents accidental cross-context pollution. (FR5)
  • Locale chips are additive — "+ de-DE" shows future locales as discoverable one-click options, not a dropdown.
  • Governance preamble in the dashed-border box — reinforces that Red Zone enforcement and a11y warnings apply from the first save, not just at publish. (FR15, FR51)
  • Modal is the right pattern here — this is a quick decision, not a workflow. Wizard is overkill for a new page; full canvas comes after "Create page →".
  • AI-scaffold tile violet-tinted — signals the Commerce Intelligence Drawer handoff without looking punitive.
