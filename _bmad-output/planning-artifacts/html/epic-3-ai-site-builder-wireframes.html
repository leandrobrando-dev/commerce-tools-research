Epic 3 Phase 3B — AI Site Builder Wireframes

The Commerce Intelligence Drawer in Create mode. The AI does not generate storefronts from a blank canvas — it observes what the operator is already editing on a populated canvas (from FR76 starter gallery, FR34–39 migration, or prior published state), infers intent from the last few actions, and offers to complete remaining sections using the tenant's governed Green Zone component library. Every completion passes through a reasoning brief the operator must approve before any pixel on the canvas changes. Optimize mode of the same drawer lives in Epic 8 (AI Experience Engine).

Design Notes

  • AI never generates first — it watches. This is inference-and-completion, not blank-canvas generation. Operator makes 2-3 edits, AI offers to finish. (FR7)
  • "AI observing" chip in context bar — the operator always knows whether the AI is idle, watching, or generating. Transparency beats surprise.
  • Inference card is evidence-forward — "last 8 edits", "14 previous landings", 87% confidence. "Your data shows" language, never "the AI thinks." (FR9)
  • Completion brief lists exact components — each one named from the governed library (FR8). Operator sees what will land before it lands.
  • Three approval modes — Approve all / Edit brief / Review one-by-one. The last respects operators who trust iteratively. (FR10)
  • Canvas placeholder shows AI offer inline — the operator sees where the proposed sections will go, not just a sidebar summary.

Design Notes

  • Streaming progress after 2s — first 2 seconds feel instant; anything longer gets the streaming-progress bar, per NFR2 (30s end-to-end with 2s streaming threshold). (FR12)
  • Per-section accept/regenerate/modify/reject — operators retain full control at component granularity, not just at the bulk-brief level. (FR10)
  • Queued sections visible but dimmed — operator sees the full plan but only the current section is actionable. Pacing is honest.
  • Sidebar shows the full queue state — Accepted / Generating / Queued. Side panel and canvas stay in sync, neither is the source of truth alone.
  • AI explicitly disclaims image generation — "I'm not generating images — just scaffolding the slot." Protects brand teams from unexpected asset generation.
  • Pause button in panel header — operator can stop the stream mid-flight. Accepted sections stay; queued sections discard cleanly.

Design Notes

  • No blank-canvas generation — the empty state teaches the model: "start by editing a section, AI completes." Frames inference-and-completion as the mental model. (FR7)
  • Historical import is an offer, not a demand — operators can "Skip · start cold." FR63 keeps the moat warming option optional.
  • Four import sources named explicitly — GA4, Hotjar, Mixpanel, Frontastic analytics — matches the Story 1.9 text and operator-familiar tools.
  • Evidence preview before import commits — "241k sessions, top pages named" — operator sees what will be pulled before clicking import.
  • Privacy disclaimer inline — "read-only, anonymized, one-time, deletable" addresses the common blocker before it's raised.
  • Pre-warm framing — not "training" — "calibrate inference confidence from Day 1" is the promise; avoids the implied "we train a model on your data" trust hit.
Wireframes are intentionally low-fidelity — dashed borders and placeholder content indicate where customer-brand content or migrated source structure will render.
